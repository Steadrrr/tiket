# 휴양림 발매 키오스크

산림청통합운영관리 사이트의 발매(입장권 구매) 페이지를 터치 키오스크용으로
단순화해서 보여주는 도구입니다. 사이트 자체를 수정하거나 로그인/결제 로직을
우회하지 않고, **Chrome 확장프로그램이 실제 페이지 위에 전체화면 오버레이를
얹어서** 손님에게는 발매유형별 카드(이름/가격/수량 ±)와 "신용카드 결제"
버튼만 보이게 합니다. 오버레이의 ±/결제 버튼 클릭은 실제 발매 화면(dhtmlx
그리드 셀, 신용카드 버튼)에 그대로 클릭 이벤트를 전달하므로, 로그인 세션과
카드결제기 연동 등 기존 사이트 동작은 전혀 바뀌지 않습니다.

## 동작 원리

`ioms.foresttrip.go.kr`은 로그인 후에도 최상위 URL이 `/main/init.do#`으로
고정된 채, 좌측 메뉴를 누르면 dhtmlx 탭 안에 **iframe**으로 화면이 로드되는
구조입니다(SPA형 MDI). 예를 들어 "현장발권 > 입장권판매" 메뉴를 누르면
`/rep/sm/sm/sptMngmeSalInsertEN/init.do?openMenuId=REPS0100` 같은 src를 가진
iframe이 탭 형태로 열립니다. 그래서 이 확장은:

1. 직원이 아침에 키오스크 PC를 켜면 Chrome이 키오스크 모드(`--kiosk`)로
   실행되며 로그인 페이지가 뜹니다.
2. 직원이 공인인증서로 평소처럼 수동 로그인합니다. (자동 로그인은 구현하지
   않았습니다 — 인증서 비밀번호를 코드에 저장하지 않기 위함)
3. 확장프로그램은 최상위 문서에서만 동작하며, `config.js`의
   `ticketFrameSrcPattern`과 일치하면서 **현재 화면에 보이는(visible)**
   iframe이 나타나는지 계속 감시합니다. (같은 iframe이 다른 탭으로 전환되어
   숨겨진 채 DOM에 남아있을 수도 있기 때문에 단순히 존재 여부가 아니라
   보임 여부까지 확인합니다)
4. 해당 iframe이 활성화되면 그 안에서 발매유형 그리드(각 유형별 이름/가격/
   －/＋ 셀이 있는 `<tr>`들)와 "신용카드" 버튼을 찾아, 최상위 문서 위에
   유형별 카드 형태의 전체화면 오버레이 UI를 띄웁니다.
5. 손님이 오버레이의 카드에서 ＋/－를 누르면 실제 그리드의 해당 셀에 진짜
   클릭 이벤트가 전달되어, 사이트 자체의 "이용상품정보"(장바구니)에 1개씩
   추가/차감됩니다. "신용카드 결제"를 누르면 실제 신용카드 버튼
   (`fn_crcrdSttlm()`)이 클릭되어, 기존에 연결되어 있던 카드결제기 결제
   흐름이 동일하게 진행됩니다.
6. 오버레이가 뜸과 동시에 확장프로그램이 브라우저 창을 **자동으로
   전체화면(키오스크 모드처럼 주소창/탭 없는 화면)으로 전환**합니다.
   `--kiosk` 플래그로 Chrome을 띄우지 않고 그냥 평소처럼 접속해도, 발매
   화면에 들어가는 순간 자동으로 키오스크 화면이 됩니다.
7. 직원이 다른 메뉴(환불, 매표소변경 등)로 탭을 전환하거나 탭을 닫으면
   오버레이가 자동으로 사라지고 평소 화면을 그대로 쓸 수 있습니다
   (전체화면 상태는 유지됩니다).
8. 화면 우측 상단에 아주 눈에 잘 안 띄는 "⌂" 홈 버튼이 있습니다. 누르면
   화면 안에 숫자 키패드가 뜨고(물리 키보드가 없어도 터치만으로 입력
   가능), 비밀번호(초기값 `1009`)를 맞게 입력하면 오버레이가 걷히고
   전체화면도 해제되어 원래 통합운영시스템 화면으로 돌아갑니다. 이후 같은
   탭을 그대로 두는 한 그 화면에서는 오버레이가 다시 자동으로 뜨지
   않으며, 페이지를 새로고침하거나 탭을 닫았다가 다시 열면 키오스크
   모드가 다시 시작됩니다.

## 발매유형 그리드의 실제 구조

실제 화면을 확인해 보니 발매유형은 dhtmlx가 순수 `<table>`로 렌더링하며,
한 행(`<tr>`)에서 확인된 셀 순서는 다음과 같습니다 (숨김 컬럼 포함):

```html
<!-- 예: "일반" 유형, 2,000원 -->
<td>일반</td>                           <!-- 유형명 -->
<td>2,000</td>                          <!-- 가격 -->
<td><font color="blue">－</font></td>   <!-- 감소 버튼 -->
<td style="display:none">0</td>         <!-- 숨겨진 수량(내부용) -->
<td><font color="blue">＋</font></td>   <!-- 증가 버튼 -->
```

"신용카드" 버튼도 확인되어 `extension/config.js`에 이미 반영되어 있습니다:

```html
<a class="btn btn-info btn-outline writeBtn" onclick="fn_crcrdSttlm();">신용카드</a>
```

`content.js`는 **절대 컬럼 번호가 아니라 "－/＋ 셀 기준 상대 위치"**로 발매
유형 행을 찾습니다 ("－" 셀의 바로 앞 두 칸을 가격/유형명으로, "－" 셀에서
두 칸 뒤를 "＋" 셀로 인식). 앞에 숨겨진 컬럼이 몇 개가 오든 영향받지
않도록 하기 위한 설계입니다. 별도 컨테이너 선택자도 필요 없습니다.

**동작이 안 될 때 진단하는 법**: 오버레이가 안 뜨고 콘솔에 "발매유형
그리드 또는 신용카드 버튼을 찾지 못했습니다" 오류가 뜨면, 개발자도구
Console 탭에 아래와 같은 진단 로그가 함께 출력됩니다.

```
[키오스크] 진단: 문서 readyState = complete
[키오스크] 진단: "－" 글자를 가진 셀 개수 = 0
[키오스크] 진단: 매칭된 발매유형 행 개수 = 0
[키오스크] 진단: 신용카드 버튼( a[onclick*="fn_crcrdSttlm"] ) 존재 = true
```

- "－" 글자를 가진 셀 개수가 0이면: 발매유형 그리드가 아직 로딩되지
  않았거나(사용일자를 먼저 선택/조회해야 나타나는 경우), 실제로는 다른
  글자(예: 반각/전각이 아닌 다른 minus 기호)를 쓰고 있는 것일 수 있습니다.
- 셀 개수는 0이 아닌데 매칭된 행 개수가 0이면: "－" 셀 주변 칸 배치가
  예상과 달라서(예: － 바로 다음 칸이 숨김 수량이 아니라 바로 ＋일 수도
  있음) `config.js`의 `ticketRow` 로직을 조정해야 합니다.
- 신용카드 버튼 존재가 false면: `config.js`의 `selectors.payButton`
  선택자를 실제 HTML에 맞게 다시 확인해야 합니다.

이 로그를 그대로 캡처해서 알려주시면 바로 원인을 확인할 수 있습니다.

## 발매유형별 예외 규칙

- `config.js`의 `excludedTypeNames`에 있는 이름(현재: 쉬자파크숙박,
  유료프로그램이용, 백운봉휴양림숙박, 시설대관, 무료주차)은 키오스크 카드
  목록에서 아예 제외됩니다. 이 유형들은 직원 창구에서만 판매됩니다.
- `config.js`의 `bulkTypeNames`(현재: 단체(일반), 단체(초중고학생))는
  최소 구매 수량이 있는 단체 유형입니다:
  - "＋"를 처음 누르면 0에서 바로 `bulkMinQty`(30)로 올라가고, 이후로는
    1씩 증가합니다.
  - "－"를 눌렀을 때 결과가 30 미만이 되면(즉 30에서 한 번 더 내리면)
    바로 0으로 초기화됩니다. 31 이상에서는 평소처럼 1씩 감소합니다.
  - 내부적으로는 실제 그리드의 ＋/－ 셀을 필요한 횟수만큼(예: 0→30은 30번)
    반복 클릭해서 실제 장바구니 수량을 맞춥니다.

## 할부 개월 수 선택 (5만원 이상 결제 시)

실제 사이트는 결제금액이 일정 금액(보통 5만원) 이상이면 "신용카드" 클릭
후 발매 화면 iframe 안에 할부 개월(일시불/2~6개월)을 고르는 작은 팝업을
띄웁니다(`fn_selectMonth()`). 우리 오버레이가 화면 전체를 덮고 있어 이
팝업은 손님 눈에 보이지 않으므로:

1. "신용카드 결제"를 누르면 실제 버튼 클릭을 전달한 뒤, 최대 6초간 그
   할부 선택 팝업이 나타나는지 지켜봅니다.
2. 나타나면 오버레이 위에 똑같은 선택지(일시불/2개월/.../6개월)를
   큼직하게 다시 보여주고, 손님이 고른 값을 실제 버튼 클릭으로 그대로
   전달합니다.
3. 5만원 미만이라 팝업이 안 뜨면(6초 안에 못 찾으면) 그냥 기존처럼
   진행됩니다.

버튼은 절대 `id`가 아니라 **버튼에 표시되는 값이 "일시불", "2개월" 등과
정확히 일치하는지**로 찾습니다(`content.js`의 `INSTALLMENT_LABELS`). 만약
실제 표시 문구가 다르면(예: "2개월" 대신 "2회" 등) 이 배열을 실제 값에
맞게 수정해야 합니다.

실제로 확인해보니 이 버튼들은 `<input>`/`<button>`이 아니라 dhtmlx 폼이
그리는 커스텀 클릭 요소였습니다:

```html
<div class="dhxform_btn" role="link" tabindex="0">
  <div class="dhxform_btn_txt">일시불</div>
  <div class="dhxform_btn_filler"></div>
</div>
```

`findInstallmentButtons()`는 이 구조(바깥 `div.dhxform_btn` + 안쪽
`.dhxform_btn_txt`의 텍스트)도 인식하도록 되어 있습니다.

**결제 중 오버레이가 갑자기 사라지는 문제**: 결제가 진행되는 동안 실제
페이지 화면이 잠깐씩 바뀌는데, 그 타이밍에 자동 재확인 로직이 끼어들어
오버레이를 다시 만들려다 실패하면 오버레이가 통째로 사라질 수 있었습니다.
"신용카드 결제"를 누르면 60초간 자동 재구성을 멈추도록 해서, 결제/할부
선택이 끝날 때까지 오버레이가 유지되도록 했습니다.

**할부 팝업이 여전히 안 뜨는 경우 진단하는 법**: 최대 10초(`waitForInstallmentButtons`의
`timeoutMs`) 안에 할부 버튼을 못 찾으면 개발자도구 Console에 아래와 같은
진단 로그가 남습니다.

```
[키오스크] 할부 팝업 진단: div.dhxform_btn 개수 = 0
[키오스크] 할부 팝업 진단: [role="link"] 개수 = 0
```

- `div.dhxform_btn` 개수가 0이면: **애초에 실제 할부 선택 팝업 자체가
  뜨지 않은 것**입니다. 결제금액이 5만원 미만이었거나(정상), 혹은 사이트
  자체 오류(`layoutSub.setSizes is not a function` 등)로 팝업 생성이
  실패했을 가능성이 있습니다. 후자라면 저희 확장 문제가 아니라 사이트
  자체 버그일 가능성이 높습니다 — 5만원 이상으로 다시 테스트했을 때도
  콘솔에 이 오류가 함께 뜨는지 확인해 주세요.
- `div.dhxform_btn` 개수가 0보다 크면(버튼 텍스트 목록도 같이 출력됨):
  팝업은 떴지만 우리가 인식하는 라벨("일시불", "2개월" 등)과 실제 텍스트가
  달라서 못 찾은 것입니다. 출력된 텍스트 목록을 그대로 알려주시면
  `INSTALLMENT_LABELS`를 맞게 수정하겠습니다.

## ⚠️ 남은 확인/조정 사항

- `config.js`의 `homeButton.password` — 초기값은 `1009`입니다. 실제 운영
  비밀번호로 바꾸는 것을 권장합니다.
- `scripts/launch-kiosk.sh` / `launch-kiosk.bat`의 `START_URL` — 현재는
  `https://ioms.foresttrip.go.kr/`로 두었습니다. 로그인 후 자동으로 이
  주소로 리다이렉트되지 않는다면 실제 로그인 페이지 주소로 바꿔주세요.
- **최대인원/정원 초과 시 알림창**: 실제 페이지는 특정 상품(숙박 연계 상품,
  프로그램 정원 등)에서 한도를 초과하면 `alert()` 경고창을 띄웁니다. 이
  경고창은 브라우저 자체의 모달이라 오버레이 위에 그대로 뜨며, 확인을
  눌러야 다음 조작이 가능합니다. 순수 "입장권"(일반/청소년 등)만 파는
  키오스크라면 거의 발생하지 않지만, 만약 자주 발생한다면 해당 상품유형은
  키오스크가 아니라 직원 판매로 안내하는 것을 권장합니다.
- 만약 다른 매표소/기관에서 그리드 컬럼 순서나 "신용카드" 버튼의 onclick
  함수명이 다르게 나온다면, 위와 같은 방식(F12 → 요소 선택 → Elements에서
  `Ctrl+C`로 outerHTML 복사, 또는 Console에서 `$0.outerHTML`)으로 확인해서
  `config.js`를 조정하면 됩니다. (이 사이트는 우클릭이 막혀 있어 페이지
  본문에서는 우클릭 메뉴가 안 뜨지만, DevTools의 Elements 패널 안에서는
  정상적으로 사용할 수 있습니다.)

## 선택자 채운 뒤 테스트하는 법

1. `chrome://extensions` 접속 → 우측 상단 "개발자 모드" 켜기
2. "압축해제된 확장 프로그램을 로드합니다" 클릭 → 이 저장소의 `extension`
   폴더 선택
3. 일반 Chrome 창(키오스크 모드 아님)으로 실제 사이트에 로그인 후 발매
   페이지로 이동해 오버레이가 정상적으로 뜨는지, 유형/수량/결제 버튼이
   실제 페이지에 잘 반영되는지 확인
4. 정상 동작 확인 후 `scripts/launch-kiosk.sh`(리눅스) 또는
   `launch-kiosk.bat`(윈도우)로 키오스크 모드 실행

## 운영 시 참고 사항

- **자동 시작**: 리눅스는 `systemd` 유저 서비스나 데스크톱 자동실행 항목에,
  윈도우는 시작프로그램 폴더나 작업 스케줄러에 launch 스크립트를 등록하면
  재부팅 시 자동으로 키오스크가 뜨게 할 수 있습니다.
- **개발자 모드 확장 경고**: 최신 Chrome은 `--load-extension`으로 로드한
  확장에 대해 가끔 "개발자 모드 확장 프로그램" 경고 배너를 띄울 수
  있습니다. 완전히 배너 없는 운영이 필요하면 확장을 `.crx`로 패키징하고
  Chrome 기업 정책(`ExtensionInstallForcelist`)으로 설치하는 방식을
  고려하세요.
- **자동 전체화면의 한계**: `chrome.windows.update(..., {state:'fullscreen'})`로
  창을 전체화면(F11과 동일한 효과)으로 만들지만, 이는 `--kiosk` 플래그로
  띄우는 진짜 키오스크 모드만큼 잠겨있지는 않습니다. 사용자가 `F11`을
  눌러 전체화면을 풀거나 `Alt+Tab`/`Alt+F4` 등으로 다른 창으로 빠져나갈
  가능성은 남아있습니다. 터치스크린만 노출하고 키보드가 물리적으로 연결돼
  있지 않은 환경이라면 실무상 문제없지만, 완전한 잠금이 필요하면
  `scripts/launch-kiosk.sh`/`.bat`로 `--kiosk` 플래그와 함께 띄우거나 OS
  레벨 키오스크 잠금(예: 우분투 kiosk 세션, 윈도우 Assigned Access)을
  추가로 적용하세요.
- **전체화면 전환이 늦게 되는 경우**: 크롬은 최근 사용자 입력(클릭/키
  입력)이 전혀 없는 상태에서 `chrome.windows.update`로 전체화면을 요청하면
  조용히 무시하는 경우가 있습니다. 그래서 오버레이가 뜨는 순간 1차
  시도를 하고, 그 이후로는 화면(오버레이 자체 버튼 포함) 아무 곳이나
  클릭하거나 키보드를 누를 때마다 성공할 때까지 자동으로 재시도합니다.
  보통 오버레이가 뜬 직후 아무 카드나 한 번만 눌러도 바로 전체화면으로
  전환됩니다.
- **오버레이 자체가 늦게 뜨는(F12를 눌러야 뜨는) 경우**: 이 사이트는
  dhtmlx가 계속 자잘한 화면 갱신을 일으켜서, "DOM 변화가 멈추면 확인"하는
  순수 디바운스 방식만 쓰면 변화가 끊이지 않아 확인 자체가 계속 밀려
  실행이 안 되는 경우가 있었습니다(개발자도구를 열어 렌더링이 잠깐 멎는
  순간에만 실행되는 것처럼 보였던 원인). 이제 0.5초마다 무조건 한 번씩
  강제로 확인하는 안전장치를 추가해서, 최악의 경우에도 0.5초 안에는
  오버레이가 뜨도록 했습니다.
- **보안 범위**: 이 확장은 화면에 보이는 UI만 재구성할 뿐, 로그인 인증이나
  결제 처리 로직 자체는 전혀 건드리지 않습니다. 카드 정보는 여전히 사이트와
  카드결제기 사이의 기존 흐름으로만 오갑니다.
- **화면 크기**: 발매유형 카드는 해상도와 무관하게 **항상 4열**로 배치됩니다
  (항목이 8개 이하면 자연히 2줄). 글자/버튼 크기는 `vh`(뷰포트 높이) 기준
  `clamp()`로 자동 조절되어, 유형 개수가 많아져도 스크롤 없이 화면 한
  장에 다 들어옵니다.
- **색상**: 기본 배색은 부드러운 하늘색 계열입니다 (배경은 연한 하늘색
  그러데이션, 카드는 흰색, ±버튼과 결제 버튼은 중간 톤의 파란색). 색을
  바꾸고 싶으면 `extension/overlay.css`의 색상 값들을 수정하면 됩니다.
- **카드 높이 정렬**: 단체 유형처럼 안내 문구(힌트)가 추가로 붙는 카드는
  일반 카드보다 위쪽 내용이 한 줄 더 많습니다. ±버튼 줄을 항상 카드 맨
  아래에 고정해서(`margin-top: auto`), 옆에 나란히 있는 카드들과 ±버튼
  높이가 어긋나지 않게 맞춰져 있습니다.
